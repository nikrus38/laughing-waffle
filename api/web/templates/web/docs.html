API «ФинТвин»

Один JSON-контракт для консоли, сайта и внешних проверок. Сервер считает правила: матчинг, реестр FinCoin, дневные лимиты и этический фильтр.

Обзор #

API обслуживает демонстрационную модель Университета 4.0: цифровой двойник студента, подбор задач партнёров, кошелёк FinCoin и журнал решений ИИ. Все данные вымышленные и помечены полем isMock; реальны только суммы FinCoin и две цифры диагностики — 34,7% и 55%.

Как устроен контракт

  • Один стартовый запрос. GET /api/bootstrap/ отдаёт всё, что нужно первому экрану консоли, вместо десяти мелких запросов.
  • Действия — командами. Отклик на задачу, прохождение модуля и начисление монет — отдельные POST-запросы.
  • Правила на сервере. Процент совпадения, лимиты и цепочка хэшей считаются на бэкенде, фронтенд их только показывает.
  • Детерминизм. Никаких внешних языковых моделей: одинаковый вход даёт одинаковый ответ, поэтому демо воспроизводимо.
Демо-режим. Вход доступен по адресу /demo-login/ с логином demo и паролем fintwin2026. Это фиксированная вымышленная персона, персональные данные не используются.

Аутентификация #

Авторизация построена на cookie-сессиях Django. Токенов в заголовке нет: браузер присылает sessionid автоматически. Любой POST или PATCH дополнительно требует CSRF-токен.

CSRF

  • GET /api/csrf/ ставит cookie csrftoken и возвращает {"ok": true}.
  • Значение cookie передаётся заголовком X-CSRFToken в каждом небезопасном запросе.
  • Консоль запрашивает токен один раз при старте и обновляет его после входа.
HTTP 
GET /api/csrf/ HTTP/1.1
Host: fintwin.duckdns.org

HTTP/1.1 200 OK
Set-Cookie: csrftoken=Zk3...; Path=/; SameSite=Lax
Content-Type: application/json

{"ok": true}

Telegram Mini App

Внутри Telegram приложение использует ту же cookie-сессию. Подпись initData проверяется серверным модулем core.services.telegram по алгоритму из документации Mini Apps; данные пользователя Telegram не сохраняются. Публичного эндпоинта для обмена initData нет — это осознанное решение демо-версии.

CORS отключён. API отвечает только на запросы со своего домена. Внешние клиенты и мобильные приложения не подключаются: это защита демо от сторонних сценариев.

Объекты #

Шесть сущностей покрывают весь контракт. Названия полей совпадают с React-типами.

Объект Ключевые поля Смысл
user id, username, displayName, course, role Учебный профиль. Роль — student или partner.
twin competencies, interests, weeklyHours, completedModules Восемь компетенций 0–100 в формате {level, target}.
task id, title, partnerLabel, required, weeks, match Задача партнёра и рассчитанный процент совпадения с объяснением факторов.
module id, title, minutes, difficulty, gains, valueTags Микромодуль на 15–45 минут с приростом по осям компетенций.

Лимиты FinCoin #

Суммы фиксированы заданием и не меняются через API. Дневной лимит ограничивает число начислений одного типа за календарный день; одно и то же основание нельзя засчитать дважды.

{% for code, title, amount, limit in coin_actions %} {% endfor %}
Действие Название FinCoin В день
{{ code }} {{ title }} {{ amount }} {{ limit }}
Зачем лимиты. Без них баллы можно нафармить активностью, а не вкладом. Правило WALLET-001 требует, чтобы рекомендации опирались на развитие, а не на размер награды.

Правила и версии #

  • Версия контракта v1 от 27 ноября 2026. Идентификаторы задач, модулей и ценностей стабильны.
  • Mock-данные. Любая вымышленная сущность содержит isMock: true; цифры 34,7% и 55% — единственные реальные показатели.
  • Ценности. Официальные формулировки не переданы, поэтому поле text равно null и интерфейс показывает «текст уточняется».
  • Доступность. Живой статус, uptime за 30 дней и инциденты — на странице /status/ и в /api/status/.

Документация собирается из того же файла, что и карточки эндпоинтов (api/web/api_docs.py), поэтому описание и код меняются вместе.
