# Карта проекта «ФинТвин» — для команды

Документ для одногруппников: что мы строим, где что лежит, как запустить и что можно
делать прямо сейчас. Читается за 15 минут, без знания Django и React.

---

## 1. Что это такое

«ФинТвин» — демонстрационная модель Университета 4.0. Это не настоящая система
университета, а интерактивный продукт для защиты проекта: комиссия сама проходит
сценарии и видит, как работают цифровой двойник, подбор задач, FinCoin и этика
алгоритмов.

Два входа:

- **Публичный сайт `/`** — лендинг для всех: что это, как работает, этика, установка.
- **Консоль `/app/`** — личный кабинет после входа: обзор, двойник, матч, кошелёк, этика.

Тот же продукт открывается в Telegram как Mini App и устанавливается как PWA
(иконка на рабочем столе или домашнем экране).

## 2. Как запустить у себя

Нужны Python 3.12+ и Node.js 20+.

```powershell
# 1. Зависимости бэкенда (один раз)
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r api\requirements.txt

# 2. База и демо-данные (один раз и после сброса)
.\.venv\Scripts\python.exe api\manage.py migrate
.\.venv\Scripts\python.exe api\manage.py seed_demo

# 3. Сервер
.\.venv\Scripts\python.exe api\manage.py runserver
```

Открыть <http://127.0.0.1:8000/>. Демо-вход: **demo / fintwin2026** (или кнопка
«Войти как демо-студент»).

Фронтенд для правок интерфейса:

```powershell
npm install
npm run dev        # http://localhost:3000, API проксируется на Django
```

Проверки перед коммитом:

```powershell
.\.venv\Scripts\python.exe -m pytest api -q   # 34 теста бэкенда
npm run test:run                              # 21 тест фронтенда
npx tsc --noEmit                              # типы
npm run build                                 # сборка консоли в dist/
```

```
│  │  └─ management/        команда seed_demo

│  ├─ app/                  роутер, оболочка, сайдбар, шапка
│  ├─ features/             экраны: home, twin, matcher, wallet, ethics, diagnostics…
│  ├─ domain/               чистая логика: matching, ledger, ethics, twin, types
│  ├─ data/                 моки для локального режима
│  └─ shared/               api-клиент, store, компоненты, утилиты
├─ api/web/static/web/      стили лендинга, service worker, бренд-ассеты
├─ brand/fa/                брендбук Финуниверситета (см. brand/fa/README.md)
├─ docs/                    решения, аналитика этапов, эта карта

└─ tests/                   unit-тесты фронтенда
```

### Кто с кем разговаривает

```
Браузер / Telegram / PWA
        │
        ├── GET /            → Django-шаблон лендинга
        ├── GET /login/      → Django-форма входа (сессия + CSRF)
        ├── GET /app/*       → React-консоль (dist/index.html)
        └── /api/*           → JSON API (Django REST Framework)
                                 │
                              SQLite (демо)
```

Важно: **правила живут на сервере**. Начисления, лимиты и цепочка хэшей нельзя
подделать из консоли браузера. Фронтенд только показывает и просит.

Если Django не запущен, консоль в dev-режиме работает на локальных моках
(`src/data`). Это сделано специально: интерфейс можно показывать даже без сервера.

## 4. Пять правил, которые надо знать наизусть

1. **Матчинг.** Балл 0–100 = 100 × (0,40·навыки + 0,30·зона роста + 0,20·интересы +
   0,10·загрузка). Пол, возраст, происхождение и средний балл не участвуют.
2. **Матч-001.** В первой тройке рекомендаций всегда есть задача на вырост. Если все
   три лёгкие — самая простая уходит ниже, причина пишется в журнал.
3. **FinCoin.** Суммы строго из задания: 20 / 100 / 50 / 40 / 150 / 70. Одно основание
   нельзя засчитать дважды, действуют дневные лимиты.
4. **Реестр.** Каждая запись хранит хэш предыдущей (SHA-256). Подмена ломает цепочку,
   кнопка «Проверить цепочку» это показывает.
5. **Двойник.** Прирост = gain × (1 − уровень/100) × доля верных ответов. Чем выше
   уровень, тем меньше прирост — убывающая отдача.

Все пять правил покрыты тестами: `api/tests/` и `tests/unit/`.

## 5. Что где менять

| Задача | Где |
| --- | --- |
| Текст на лендинге | `api/web/templates/web/landing.html` |
| Стили лендинга | `api/web/static/web/landing.css` |
| Тексты интерфейса консоли | компоненты в `src/features/**` |
| Цвета и типографика | `src/index.css` (токены), `api/web/static/web/landing.css` |
| Добавить задачу партнёра | `api/core/seed_data.py` → `TASKS`, затем `seed_demo` |
| Добавить микромодуль | `api/core/seed_data.py` → `MODULES` |
| Изменить формулу матчинга | `api/core/services/matching.py` + `src/domain/matching.ts` |
| Правила FinCoin | `api/core/services/ledger.py` |
| Правило этики | `api/core/services/ethics.py` + `seed_data.py` |
| Барьеры диагностики | `api/core/seed_data.py` → `BARRIERS` |
| PWA (манифест, офлайн) | `api/web/views.py`, `api/web/static/web/sw.js` |
| Логотип и иконки | `api/web/static/web/brand/`, исходники в `brand/fa/` |
| Брендбук и правила | `brand/fa/README.md` |

Правило: если меняете демо-данные — меняйте их в `seed_data.py`, а не в базе руками.
Иначе у другого человека данные не обновятся.

## 6. Роли в команде и первые задачи

| Роль | Что делать | Первая задача |
| --- | --- | --- |
| Дизайнер | макеты, иконки, скриншоты | собрать 6 скриншотов консоли в 390×844 и 1440×900 |
| Аналитик этапа 1 | барьеры, потоки данных, прогноз | проверить 20 барьеров в `seed_data.py` на правдоподобие |
| Аналитик этапов 2–3 | траектория, патенты, декомпозиция | дописать `docs/stage2-trajectory.md` |
| Frontend | экраны и состояния | пустое/загрузочное/ошибочное состояние для «Матча» |
| Backend | API, тесты, деплой | PostgreSQL вместо SQLite + переменные окружения |
| QA | сценарии, доступность | прогнать три сценария на 360×640 и 1440×900 |
| Презентация | речь и слайды | собрать черновик по `docs/defense-script.md` |

Что **нельзя** делать без согласования: менять официальные формулировки ценностей,
добавлять реальные логотипы партнёров, подключать платные сервисы, коммитить секреты.

## 7. Что уже готово и что честно не готово

Готово:

- лендинг, вход/регистрация, демо-вход;
- консоль: обзор-дашборд, двойник, матч, кошелёк, этика, диагностика, траектория,
  декомпозиция, патенты, сценарии;
- серверные правила: матчинг, реестр с хэш-цепочкой, лимиты, двойник, журнал этики;
- PWA: манифест, service worker, иконки, баннер установки;
- 34 теста бэкенда, 21 тест фронтенда, проверка типов, сборка.

Не готово / требует команды:

- официальные формулировки 10 ценностей (сейчас «текст уточняется»);
- подтверждение источника цифр 34,7% и 55%;
- хостинг и домен (нужен HTTPS для Telegram и PWA);
- PostgreSQL и боевые настройки (сейчас SQLite и `DEBUG=1`);
- e2e-тесты Playwright на три сценария;
- презентация и сценарий защиты.

## 8. Демо на 3 минуты (для проверки)

1. Открыть `/` → «Открыть демо» → консоль.
2. «Матч»: показать три фактора совпадения и задачу «на вырост».
3. «Откликнуться» → «План первого месяца» → «Перейти к двойнику».
4. Пройти микромодуль → +20 FinCoin, радар вырос.
5. «Кошелёк» → «Проверить цепочку» → «Цепочка целостна».
6. «Этика» → «Искушение» → ползунок до 100% → алгоритм всё равно ведёт по пути развития.
7. «Сценарии» → «Сбросить демо».

Если что-то сломалось — сначала «Сбросить демо», потом перезапустить сервер.
